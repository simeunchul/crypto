Crypto Swing — 옵션 Y/Z 진단 + long-short 가설 발견

생성: 2026-05-23 · 작업자: simeunchul · 관련: backtest_crypto_optY_60d_20260523_170511

한 줄 결과. 어제 -$300 손실 → 옵션 Y (closed-bar 신호 + 차단 플래그) 적용 → 1시간 운영 결과 7종 trail-stop (지갑 -413) → 5m polling backtest 로 옵션 Y 가 backtest B (Sharpe +2.73) 보다 압도적으로 나쁨을 확인 (Sharpe -0.29) → 옵션 Z (trail 도 봉 마감만) 도 비슷하게 나쁨 (-0.07). 진단 결과 sweep 우승자 B 는 long-short 모드, live 봇은 long-only — 차단 후 회전 메커니즘이 작동 안 함. 이게 backtest 와 live 의 근본 격차 원인.

1. 무엇을 시도했는지

1-1. 시작점 — 어제 -$300 손실

swing 모드 18종 + 5분 polling + trail-2% 로 24시간 운영 결과 지갑 11,032 → 10,725 USDT (-$307). log 분석 결과 24시간에 trail-stop 45회 + OPEN 49회 — 평균 15분마다 한 번 매매. NEAR/INJ 같은 신흥 알트가 같은 종목을 13/11번 trail-OPEN 반복하는 명백한 휩쏘.

1-2. 옵션 Y 적용 (closed-bar 신호 + 차단 플래그)

휩쏘 원인 2가지 가설로 진단:

  • 매 5m polling 시 진행 중인 4h 봉의 잠정 close 로 MA 재계산 → 봉 안 신호 흔들림
  • trail 발동 후 즉시 같은 신호로 재진입 (차단 메커니즘 부재)

둘 다 fix:

  • closed_kl = [k for k in kl if open_time + 4h <= now] — 진행 중 봉 제외
  • stopped_until_signal_change 도입 — trail 발동 후 같은 방향 신호로 차단

1-4. 옵션 Z 적용 — trail 평가도 4h 봉 마감 시점에만

옵션 Y의 5m polling trail 이 봉 안 spike 에 너무 민감하다는 추가 가설. 해결: trail 평가도 4h 봉 마감 직후만, closed bar 의 close 값 사용. 이게 backtest B (4h bar-by-bar) 와 정확히 일치하는 방식이어야 함.

2. 진짜 원인 발견 — long-short vs long-only

2-1. 차이의 본질

backtest B (sweep 우승자) live 봇 (지금 운영) ────────────────────────────── ────────────────────────────── strat_trend (long-short) --allow-short 안 줌 (long-only) sig = +1 또는 -1 sig = 0 또는 +1 (fast > slow → +1) (fast > slow → 1, else 0) (fast < slow → -1) trail 발동 후 동작: trail 발동 후 동작: state = 0 state = 0 stopped_until_signal_change = 1 stopped_block = 1 다음 bar : 다음 bar : sig=+1 → 차단 sig=1 → 차단 sig=-1 → 차단 해제 + SHORT 진입 sig=0 → 차단 해제 (대기) (sig 0 자체가 거의 안 나옴!) 거래 회전: 거래 회전: trail → SHORT → cross-up → LONG → ... trail → 영원히 대기 (계속 거래 회전) (cross-down 봉 마감까지)

2-2. 영향 — 강세장에서 long-only 의 함정

4h+12/48 MA 는 강세 추세에서 fast > slow 가 며칠~수주 유지됨. long-short backtest 에서는 trail 후 SHORT 진입했다가 다시 LONG 으로 회전하며 거래 횟수 유지. long-only 에서는 sig=1 이 계속 나와서 trail 후 영원히 차단.

5. 추천 — 옵션 ① (long-short 도입)

가장 backtest 일치하는 길. --allow-short 한 줄 추가만으로 live 가 sweep 우승자 B 와 같은 동작. backtest 평균 Sharpe +2.73 이 그대로 적용 기대.
SHORT 도입 시 추가 고려.
  • USDT-M perpetual 은 SHORT 도 가능 (현재 메인 모드)
  • SHORT 진입 시 funding rate 부담 발생 (LONG 과 반대 방향). 강세장에서는 LONG 이 funding 받음, SHORT 가 지불
  • 현재 코드 (compute_signal) 는 SHORT 지원, 다만 entry 자본 분할이 LONG 과 동일하게 처리되는지 검증 필요
  • backtest sweep 자체가 long-short 기준 이라 long-short live 가 가장 자연스러운 매치

6. 비전공자용 요약 (TL;DR)

  1. 어제 -$300 손실의 원인은 휩쏘 (같은 종목 청산-진입 반복)
    → 옵션 Y (closed signal + 차단 플래그) 로 1차 수정
  2. 옵션 Y 의 1시간 운영 결과는 정확히 의도대로 — 7종 모두 peak -2% 닿자 자동 청산
    → 시장 약세 + 정밀한 trail 의 자연스러운 결과
  3. 그런데 backtest 비교에서 옵션 Y/Z 모두 backtest B (Sharpe +2.73) 에 한참 못 미침
    → 옵션 Y -0.29, 옵션 Z -0.07. 거의 0 수익.
  4. 진짜 원인 발견 — sweep 우승자 B 는 "LONG 과 SHORT 둘 다 진입" (long-short)
    → live 봇은 "LONG 만" (long-only). 강세 추세에서 trail 발동 후 SHORT 못 가니 영원히 대기.
  5. 해결책 — live 봇에 --allow-short 추가하면 backtest 와 일치
    → 60일 평균 Sharpe +2.73, 수익 +12.76% 기대
  6. 지금 봇은 옵션 Z 로 가동 중 (잔여 INJ + BNB LONG 2종)
    → 결정 대기: ① SHORT 허용 (추천) / ② 차단 완화 / ③ 그대로 유지 / ④ 어제 동작 복귀
